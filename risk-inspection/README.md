# Инспекция участков — тестовая модель

Веб-админ-панель для журнала обращений по рискам (карьеры, участки),
в визуальном стиле проекта «Гидрогеологический мониторинг». QR-код и
мобильная форма для полевых сотрудников уже существуют на предприятии
и этим модулем не затрагиваются — панель только читает/редактирует
данные, которые форма пишет в SQL Server.

## Запуск локально

Статические файлы, сборка не нужна. Например:

```bash
cd risk-inspection
python3 -m http.server 8080
# открыть http://localhost:8080
```

## Режим работы

Сейчас (`config.js` → `API_BASE_URL: null`) панель работает на
локальных данных в `localStorage` браузера — это тестовая модель для
демонстрации UI и логики. Реальные сетевые данные подключаются позже:
инструкция для IT — в [`BACKEND_INTEGRATION.md`](./BACKEND_INTEGRATION.md).

Чтобы сбросить тестовые данные к исходному состоянию — в консоли
браузера: `RiskApi._debugResetSeed()`.

## Разделы панели

- **Журнал Обращений** — список всех обращений с сортировкой, поиском,
  пагинацией. Двойной клик по строке открывает карточку с 2 вкладками:
  «Информация по обращению» (редактируемые поля + фото) и «Статус
  обращения» (открыто/закрыто, форма закрытия с фото результата).
- **Карта** — план участка (Карьер ЮРГ/СРГ/ДСК) с точками обращений,
  спроецированными по их координатам X/Y (СК-42); клик по точке
  открывает карточку обращения. Zoom колёсиком, перетаскивание для
  панорамирования. И схема, и точки фильтруются по **неделе** — выбор
  недели вверху карты, по умолчанию открывается самая свежая загруженная.
- **Справочники** — Названия участков, Зафиксированные риски, Индикаторы
  опасностей (каскадно от риска), Уровни опасности, Схемы участков
  (загрузка PDF/изображения плана **на каждую неделю отдельно** +
  калибровка по 2 точкам — тот же расчёт, что и в проекте
  «Гидрогеологический мониторинг». Старые недели остаются в истории и
  доступны через переключатель недель, не затираются новой загрузкой;
  при первой загрузке новой недели границы координат подставляются с
  прошлой недели того же участка — можно поправить, а не калибровать
  заново. Удаление стирает схему только выбранной недели).
- **Службы → Уведомления** — какие e-mail получают письма по каждому
  риску/уровню опасности.
- **Службы → Контакты** — список ответственных лиц.

## Известные ограничения тестовой модели

- Данные хранятся в `localStorage` — видны только в том браузере, где
  их создали. Реальная синхронизация между телефоном (форма) и панелью
  появится после подключения API (см. `BACKEND_INTEGRATION.md`).
- Фото в демо-данных — сгенерированные заглушки, не настоящие снимки.
- Изображение схемы участка тоже хранится как base64 в `localStorage` —
  в боевом API должно стать файлом на сервере (см. `BACKEND_INTEGRATION.md`, раздел 2.2).
- Отправка e-mail-уведомлений не реализована на фронтенде — это
  серверная задача, описанная в `BACKEND_INTEGRATION.md` (раздел 2.3).
