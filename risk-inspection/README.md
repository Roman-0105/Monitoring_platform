# Инспекция участков — тестовая модель

Веб-админ-панель для журнала обращений по рискам (карьеры, участки),
в визуальном стиле проекта «Гидрогеологический мониторинг». QR-код и
мобильная форма для полевых сотрудников уже существуют на предприятии
и этим модулем не затрагиваются — панель только читает/редактирует
данные, которые форма пишет в SQL Server.

## Запуск локально

Статические файлы, сборка не нужна. Например:

```bash
cd risk-inspection
python3 -m http.server 8080
# открыть http://localhost:8080
```

## Режим работы

Сейчас (`config.js` → `API_BASE_URL: null`) панель работает на
локальных данных в `localStorage` браузера — это тестовая модель для
демонстрации UI и логики. Реальные сетевые данные подключаются позже:
инструкция для IT — в [`BACKEND_INTEGRATION.md`](./BACKEND_INTEGRATION.md).

Чтобы сбросить тестовые данные к исходному состоянию — в консоли
браузера: `RiskApi._debugResetSeed()`.

## Разделы панели

- **Журнал Обращений** — список всех обращений с сортировкой, поиском,
  пагинацией. Двойной клик по строке открывает карточку с 2 вкладками:
  «Информация по обращению» (редактируемые поля + фото) и «Статус
  обращения» (открыто/закрыто, форма закрытия с фото результата).
- **Карта** — план участка (Карьер ЮРГ/СРГ/ДСК) с точками обращений,
  спроецированными по их координатам X/Y (СК-42); клик по точке
  открывает карточку обращения. Zoom колёсиком, перетаскивание для
  панорамирования. И схема, и точки фильтруются по **неделе** — выбор
  недели вверху карты, по умолчанию открывается самая свежая загруженная.
  - **Раскраска точек** — переключатель «Статус / Уровень опасности / Тип
    риска» над картой; режимы взаимоисключающие (смена сбрасывает
    предыдущий), цвета берутся из вкладки «Настройка цветов».
  - **Показывать** — независимый от раскраски фильтр видимости точек по
    статусу обращения (все / только открытые / только закрытые);
    скрытые точки не рисуются и не кликаются.
  - **Слои (🧩)** — панель, открывающаяся и остающаяся статично открытой
    по кнопке (не закрывается кликом мимо, как и «Условные обозначения»
    📋), с двумя чекбоксами — включить/выключить **разломы** и **домены**
    участка целиком. Только просмотр: геометрия не создаётся и не
    удаляется из панели, редактировать её нельзя. Логика отрисовки
    (сплошные полупрозрачные линии разломов, залитые и подписанные
    полигоны доменов) — порт `faults.js`/`domens.js` из проекта
    «Гидрогеологический мониторинг», геометрия — реальные координаты
    карьера ЮРГ (см. `seed-geology.js`). Разломы/домены привязаны к
    участку целиком, не к неделе (статичная геология).
- **Справочники** — Названия участков, Зафиксированные риски, Индикаторы
  опасностей (каскадно от риска), Уровни опасности, Схемы участков
  (загрузка PDF/изображения плана **на каждую неделю отдельно** +
  калибровка по 2 точкам — тот же расчёт, что и в проекте
  «Гидрогеологический мониторинг». Старые недели остаются в истории и
  доступны через переключатель недель, не затираются новой загрузкой;
  при первой загрузке новой недели границы координат подставляются с
  прошлой недели того же участка — можно поправить, а не калибровать
  заново. Удаление стирает схему только выбранной недели), Настройка
  цветов (цвета уровней опасности, типов риска, линий разломов и
  доменов — используются на вкладке «Карта»; правки применяются сразу).
- **Службы → Уведомления** — какие e-mail получают письма по каждому
  риску/уровню опасности.
- **Службы → Контакты** — список ответственных лиц.
- **Отчёты** — формируется по клику (не по расписанию — см. ниже),
  используя только уже существующие методы `RiskApi`.
  - **Настройки** — период (пресеты «Сегодня/Неделя/Месяц/Квартал» или
    произвольные даты «С»/«По»), фильтры по статусу, уровню опасности,
    типу риска, порог просрочки для критических («СТОП!») обращений в
    днях, переключатели слоёв карты (разломы/домены), список участков
    (чекбоксы).
  - **Содержимое** — общая сводка (KPI-карточки: всего/открыто/закрыто/%
    закрытых/среднее время закрытия) по всем выбранным участкам, затем
    для каждого выбранного участка — отдельный раздел (в печати —
    отдельная страница): свои KPI-карточки, разбивка по уровням
    опасности, разбивка по типам рисков, таблица просроченных
    критических обращений (если есть), и карта участка — **отдельный
    снимок на каждую неделю периода, в которой были обращения** (недели
    без обращений и участки без единого обращения за период пропускаются;
    если для недели нет откалиброванной схемы — статистика всё равно
    показывается, просто без карты). Снимки рисуются той же функцией, что
    и живая интерактивная карта (`renderMapScene` в `ui-map.js`), поэтому
    всегда визуально совпадают с вкладкой «Карта».
  - **Печать / PDF** — кнопка «🖨️ Печать / PDF» вызывает `window.print()`
    (правила печати — в `styles.css`, `@media print`); отдельного экспорта
    в файл нет, PDF получается через диалог печати браузера («Сохранить
    как PDF»).
  - Автоматическая периодическая рассылка отчётов по расписанию (e-mail)
    **сознательно не реализована** — требует бэкенда с планировщиком, см.
    примечание в `BACKEND_INTEGRATION.md`.

> **Откуда разломы/домены на демо-карте «Карьер ЮРГ».** Это настоящая
> геология (437 линий разломов, 5 полигонов доменов), перенесённая из
> `faults.js`/`domens.js` проекта «Гидрогеологический мониторинг» — тот
> же самый карьер, только оси X/Y в двух проектах подписаны наоборот
> (диапазон точек после перестановки координат почти идеально ложится в
> калибровку демо-схемы этого участка — совпадение не случайное). См.
> `seed-geology.js`. «Карьер СРГ» и «ДСК» — без геологии и без схемы,
> это демонстрация состояния «данных ещё нет», а не недосмотр.

## Диагностика (для отладки с разработчиком)

Раньше о любой ошибке узнавали, только если кто-то догадался открыть
devtools-консоль браузера и прислать скриншот. Теперь два инструмента
(`ui-diagnostics.js`):

- **Красный баннер вверху страницы** появляется сам при любой
  необработанной ошибке и остаётся видимым, пока его не закроют — не
  нужно ничего специально открывать, ошибку сразу видно.
- **Кнопка 🩺 в шапке** (рядом с переключателем темы) — по клику копирует
  в буфер обмена JSON-снимок текущего состояния: какая вкладка открыта,
  что выбрано на карте (участок/неделя/фильтры/счётчики слоёв), сколько
  записей в каждой таблице, и список последних ошибок (если были). Это
  же самое можно скопировать из баннера кнопкой «📋 Скопировать всё».

При любой странности в интерфейсе — нажать 🩺 (или кнопку в баннере,
если он появился) и прислать вставленный текст вместо/вместе со
скриншотом: это даёт куда более точную диагностику, чем визуальный
осмотр экрана.

## Известные ограничения тестовой модели

- Данные хранятся в `localStorage` — видны только в том браузере, где
  их создали. Реальная синхронизация между телефоном (форма) и панелью
  появится после подключения API (см. `BACKEND_INTEGRATION.md`).
- Фото в демо-данных — сгенерированные заглушки, не настоящие снимки.
- Изображение схемы участка тоже хранится как base64 в `localStorage` —
  в производственном API должно стать файлом на сервере (см. `BACKEND_INTEGRATION.md`, раздел 2.2).
- Отправка e-mail-уведомлений не реализована на фронтенде — это
  серверная задача, описанная в `BACKEND_INTEGRATION.md` (раздел 2.3).
